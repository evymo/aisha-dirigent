# docker-compose.coolify-source-broker.yml — notes

Prose extracted from `docker-compose.coolify-source-broker.yml` by `scripts/compose-extract-notes.mjs`.
The compose file is passed to Coolify as a command-line argument and competes
with ARG_MAX, so it carries configuration only.

Each heading is the configuration line the note was attached to.

## `services:`

============================================================================
docker-compose.coolify-source-broker.yml
============================================================================
OPTIONAL, OPT-IN federation broker (svc-source-broker) — a first-class AISHA
stack overlay, on par with coolify-openclaw.yml / coolify-llm-gateway.yml.

It federates an EXTERNAL source application's users into an aisha session:
  source app (OTP + mantra) → svc-source-broker → gateway /token-exchange →
  role=authenticated aisha session for an already-existing email.

FULLY env-driven from the tenant env (config/domains-<tenant>.env, generated by
scripts/init-new-tenant.sh + the platform secrets from generate-secrets.mjs).
This is the SINGLE source of the broker's deploy shape — there is no per-tenant
copy (the tenant supplies only env). Required vars fail the deploy if unset.

Deployed as the `source-broker` stack (tier=optional): cold-start provisions
the Coolify app ONLY when SOURCE_API_URL is configured (coolify-story-init.sh
gate), so a non-federated fork never gets this app. Discovery + env sync are
the standard optional-stack path (coolify-deploy-init.sh).

## `image: svc-source-broker:${IMAGE_TAG:-latest}`

No `args:` here on purpose. It used to be present carrying ONLY comments
— an empty value where compose requires a mapping — so every build died
at validation with "services.svc-source-broker.build.args must be a
mapping". It shipped that way in the same commit that made this a
first-class stack (cc2e40e7) and survived until 2026-07-20, because that
commit's provisioning gate meant the app was never created and this file
was therefore never built. Coolify injects the platform build ARGs into
the Dockerfile itself (42 of them, across both stages), exactly as it
does for the sibling optional stacks, none of which declare `args:`.

### `args:` + `secrets: [git_token]` (2026-09-14)

`args:` is back, and this time it carries values: the three
`SOURCE_ADAPTER_OVERLAY_*` build ARGs of the `source-adapters` stage, which
clones the instance overlay and builds the source adapters it declares in
`source-adapters/<name>/`. Same shape as `docker-compose.coolify-keycloak.yml`
(theme overlay): explicit args without nested interpolation (Coolify cannot
render it), the token through the `git_token` BuildKit secret, never a
build ARG.

URL and ref are derived by env-doctor from `AISHA_INSTANCE_DATA_GIT_URL`
without credentials; the cachebust is refreshed by `aisha-redeploy`,
`scripts/deploy/refresh-overlay-cachebust.sh` and cold-start. Before this, a
fork carried its adapter as a workspace plus Dockerfile lines — the instance
name inside the fork core, 62 findings of `stack-nesmi-znat-jmeno-instance`.

## `POSTGRES_URL: "${AISHA_DB_URL}"`

── aisha side ──
The service reads POSTGRES_URL; the platform emits AISHA_DB_URL. Mapping
the two here is what compose is for. It used to be `${POSTGRES_URL:?}`, a
name NOTHING in the stack emits, so the first genuine provisioning failed
env validation on a variable no operator could have known to set.

PLAIN, UNNESTED reference on purpose. `${POSTGRES_URL:-${AISHA_DB_URL:?msg}}`
looks reasonable and does not work here: Coolify does not evaluate nested
${} defaults, so it took the `:?` text ITSELF as the value — the container
came up with POSTGRES_URL literally set to "set POSTGRES_URL (aisha db) in
the tenant env" and li-driver died on `getaddrinfo ENOTFOUND base`. And
because Coolify registers every key a compose declares, the bogus value
was written back over AISHA_DB_URL for this app too (same trap as
POTOK_CAPABILITIES, 0297dc94). Keep compose interpolation to one level.

## `AISHA_GATEWAY_URL: "${AISHA_GATEWAY_URL:-http://gateway:3001}"`

With the intranet key set, the gateway mints role=authenticated for an

## `SOURCE_API_URL: "${SOURCE_API_URL:-}"`

── source side (the external source app + its read-replica) ──
FEDERATION LANE — required only when this lane is active, i.e. when
SOURCE_API_URL is set. These used to be `:?` (hard-required), which meant
the broker could not boot at all without an external source app — and with
it the li-driver below, the ONLY writer into li_*, was unreachable for
every instance that just wants to replay local-ingest bundles. config.ts
now enforces them per-lane (laneEnv), so the check lives where it can tell
the two lanes apart instead of in a blanket compose guard.

## `SOURCE_WEBHOOK_HMAC_SECRET: "${SOURCE_WEBHOOK_HMAC_SECRET:?set SOURCE_WEBHOOK_HMAC_SECRET — cold-start generates it; empty means the env sync failed}"`

`:?` on purpose, unlike the two operator-supplied vars above. This one is
PLATFORM-GENERATED — generate-secrets.mjs always produces it — so it is
available on every deployment regardless of which lane is armed. An empty
value therefore never means "federation is off"; it means the env push
did not land, and that must fail the deploy rather than boot a broker
whose webhook authentication silently accepts nothing.

## `LOCAL_INGEST_DROP_DIR: "${LOCAL_INGEST_DROP_DIR:-}"`

── DROP-REPLAY LANE — local-ingest export bundles → li_* ──
Independent of the federation lane (server.ts keeps them in separate
failure domains). Set LOCAL_INGEST_DROP_DIR to arm li-driver; leave it
empty and the driver stays off, exactly like an unconfigured plugin.

The drop is a HOST PATH, not the local-ingest container's volume, because
the producer is the analyst box: local-ingest "runs on an analyst
machine, stays loopback-only, and the stack NEVER reaches into it"
(li-driver.ts). It ships verify-gated bundles here over rsync/rclone or
any other transport the operator prefers; the stack only ever reads what
has landed in this directory, and never calls back to the producer.
Binding a host path (rather than the optional app's named volume) also
keeps this service deployable when local-ingest is not installed at all.

## `- "ingest-drop:/data/ingest-drop:ro"`

Drop location for the drop-replay lane. READ-ONLY on purpose: li-driver
keeps its cursor in the DB (audience_broker_sync_state.metadata), never in
the drop, so it has no reason to write here — and a read-only mount makes
that structural rather than a promise. The host path is created by the
daemon if absent, so this stays valid while the lane is disarmed.
A NAMED VOLUME, deliberately — not a host path, and not an env var.

Not an env var: Coolify interpolates ${VAR} inside `environment:` but NOT
inside `volumes:` — measured 2026-07-20 with the variable present and
correct in the application's own env, the rendered compose still took the
default while the environment block resolved fine. A configurable mount
source is a promise this platform cannot keep, and it fails silently: the
container comes up on an empty directory and the lane drains nothing.

Not a host path either: a bind mount makes the drop a piece of host
layout the repository does not own. It has to be created out of band,
needs root to hand over, does not survive a wipe or a move to another
node, and pins this service to whichever machine the producer wrote to.
Docker creates and owns a named volume, so none of that applies.

Bundles are delivered into it from the host that runs the container
(docker cp, or a throwaway container mounting it rw). That is fine for a
local/dev lane and needs no elevated privileges. The production transport
is object storage — see the drop-lane notes above.

## `test: ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1:8090/healthz || exit 1"]`

wget, not curl — curl is NOT in this image, so the probe could only ever
fail ("sh: curl: not found", failing streak 219 on the first real
deployment, while the service was listening and li-driver was running).

127.0.0.1, not localhost — this image's /etc/hosts maps localhost to BOTH
127.0.0.1 and ::1, busybox wget tries the IPv6 entry first, and the server
binds IPv4 only: "can't connect to remote host: Connection refused" while
http://127.0.0.1:8090/healthz answers {"status":"ok"}. The `localhost`
form used elsewhere in this stack is only safe for services that bind all
interfaces.

### Proč PEVNÁ hostitelská cesta (2026-07-30)

Původní `ingest-drop:` byl Docker-managed svazek — a právě proto do něj z
local-ingestu nikdy nic nedoteklo: každý stack dostal svůj vlastní, prázdný.
Tři tvary, které NEFUNGUJÍ, ať se k nim nikdo nevrací:

1. **pojmenovaný svazek bez `external`** → Compose založí vlastní prázdný.
2. **`external: true` + `name: ${LOCAL_INGEST_OUT_VOLUME}`** → Coolify
   transformer definici přepíše na `<uuid>_ingest-drop`; `external` i `name`
   zahodí. Doloženo labelem `com.docker.compose.volume` na živém svazku
   vytvořeném deployem z mainu, který `external` má. Git správně, runtime jinde.
3. **bind na `/var/lib/docker/volumes/${VAR}/_data`** → shodila brána
   `coolify-compose-compliance`: interpolace ve zdroji volume je v Coolify
   command-injection vektor. Brána měla pravdu.

Platný tvar je `/srv/aisha/drop/local-ingest` — pevná cesta, kterou bindují OBA
strany (broker `:ro`, local-ingest jako svůj `/data/out/export`). Nemá
interpolaci, neváže se na jméno svazku ani UUID appky a obslouží oba
producenty: kontejnerový local-ingest i lokální box přes ssh — což je přesně
tvar, který předpokládá provozní návod instance (`ingest/NAVOD…`, fáze B3:
`RIQ_INGEST_DROP=user@host:/srv/aisha/drop/local-ingest/`).

Adresář nevyžaduje přípravu: Docker ho při startu kontejneru vytvoří.

## `SOURCE_ADAPTER_PLUGIN_ENTRY: "${SOURCE_ADAPTER_PLUGIN_ENTRY:-}"`

── source-adapter plugin (in-process live-read adapter) ──
The broker plugin host loads this at boot; without it every
/source/:storyId/{kpi,engagement,member} route answers 501 not_configured.
ENTRY je absolutní cesta, kam Dockerfile zkopíroval SESTAVENÝ plugin.
Který plugin to je, ví INSTANCE — platforma zná jen mechanismus, proto se
obojí deklaruje, ne dosazuje. Prázdné ENTRY = federační pruh není zapojen
a /source/* odpovídá 501 not_configured; to je legitimní stav instalace
bez zdrojového systému, ne chyba.
STORY_ID se musí rovnat UUID zaseté řádky partner_stories daného zdroje
(instanční seed) a hodnotě SOURCE_STORY_ID v Appsmith.
Adaptér si pg DSN bere ze SOURCE_PG_URL výš (binding auth_secret_ref
= env:SOURCE_PG_URL) — žádný samostatný přihlašovací údaj.

## `ingest-drop-pull:`

── Doprava balíků: bucket ↔ drop ────────────────────────────────────────────
⛔ NAMĚŘENO 2026-09-06: drop byl `bind mount` hostitelské cesty v OBOU stacích,
jenže engine (placement experimental) a broker (backend) běží na RŮZNÝCH

⛔ NAMĚŘENO 2026-09-16 v produkci instance: s `--watch` se nepřeneslo NIC.
Balíček vzniká přesunem hotového adresáře (staging → export, aby doprava nikdy
neviděla rozepsaný balíček) a inotify do přesunutého adresáře NEZANOŘÍ — o souborech
uvnitř se hlídání událostí nikdy nedozví. Balíček ležel v `/drop/export`, bucket měl
0 objektů, a po restartu sidecaru ho úvodní úplný průchod nahrál (40 objektů za 10 s).

Klíč je SCOPED na jediný bucket (politika `ingest-drop-rw`, storage-init v jádru) —
root pověření se do dalších stacků nešíří.

## `if timeout 300 rclone copy drop:ingest-drop/$${INGEST_DROP_PREFIX} /drop 2>&1; then`

⛔ BEZ `--watch` (naměřeno 2026-09-13). Smyčka stála na předpokladu, že
`mc mirror --watch` skončí, když spojení spadne. Neskončí: po restartu MinIO
při nasazení jádra proces pět dní žil, dokola hlásil `unexpected EOF`
a nezrcadlil nic, takže se smyčka k novému pokusu nikdy nedostala. Čerstvý
`--watch` ze stejného kontejneru přitom prošel hned — vadný byl jen ten
jeden dlouho žijící stream.

Jednorázové zrcadlení v intervalu 60 s nemá spojení, které by mohlo zůstat
viset, a `timeout` hlídá i uvízlý přenos. rclone žádný `--watch` nemá; tvar
(průchod, otisk času, spánek) zůstal beze změny. Balíky jsou dávkové exporty, pár
desítek sekund zpoždění na nich nic nemění. Politika `ingest-drop-rw`
naslouchání dál povoluje, jen ho tenhle sidecar nepotřebuje.

Po každém ÚSPĚŠNÉM běhu se do `/tmp/drop-sync.ok` zapíše čas.

**Prázdný prefix není porucha (naměřeno 2026-09-20).** Dokud do bucketu nikdo
nenahraje první balík, prefix neexistuje a `mc mirror` skončí `rc=1` s
„Object does not exist". Doprava přitom funguje — alias se postavil a bucket
odpovídá. Do 2026-09-20 z toho bylo TRVALÉ selhání: značka se nezapsala,
sonda po 420 s prohlásila kontejner za nemocný a Coolify celou appku za
`unhealthy` (naměřeno na jedné instanci forku: 29 hodin, 250+ kol, zdravý
broker i mesh-ingress vedle). Smyčka proto rozlišuje dva stavy:

| stav | jak se pozná | co udělá |
|---|---|---|
| prázdný prefix | `does not exist` A `mc ls drop/ingest-drop` projde | zapíše značku (doručeno nic), zahlásí JEDNOU |
| skutečná porucha | cokoli jiného, nebo bucket neodpovídá | značku nezapíše, hlásí i výstup `mc` |

Rozdíl je v tom, KDO neodpovídá: bucket (porucha doručení) versus obsah
(zatím nic k doručení). Značka `/tmp/drop-sync.prazdno` drží „už jsem to
řekl", aby z prázdného bucketu nebyl log plný opakování; při skutečné
poruše se maže, takže návrat do prázdna se zase ohlásí.

## `test: ["CMD-SHELL", "test -f /tmp/drop-sync.ok && [ $$(( $$(date +%s) - $$(cat /tmp/drop-sync.ok) )) -lt 180 ]"]`

Zdravý = poslední ÚSPĚŠNÉ zrcadlení není starší než 3 minuty. Měří se
doručení, ne existence procesu: proces, který žije a nezrcadlí, byl přesně
ta porucha, kterou předchozí `pgrep` nemohl vidět (viz brána
`bucket-ma-sveho-zakladatele` — Access Denied 2026-09-07, `unexpected EOF`
2026-09-13, pokaždé „healthy" nebo slepý healthcheck).

Obraz `mc` nemá `pgrep`, `grep`, `awk` ani `find`; `date`, `cat`, `test`
a aritmetiku shellu ano. Ověřeno lokálně proti MinIO
`RELEASE.2025-09-07T16-13-09Z`: první běh healthy, nový balík za ~10 s,
výpadek MinIO → unhealthy bez zaseknutí, návrat MinIO → healthy za ~15 s
bez restartu kontejneru.
## `test: ["CMD-SHELL", "[ $$(( $$(date +%s) - $$(cat /tmp/last-sync) )) -lt 300 ]"]`

Zdraví = KDY naposledy průchod DOBĚHL, ne že proces existuje. Zaseknuté zrcadlení
má živý pid a nepřenese nic; otisk času je jediné, co odliší „běží" od „veze".
Práh 300 s = pětinásobek intervalu průchodu, takže jeden pomalejší průchod
(velké kb_artifact) kontejner neshodí. Na otázku „došel balík?" dál odpovídá
kurzor brokeru, ne healthcheck.

celou dobu „healthy", zatímco bucket zůstal prázdný — viz poznámka u `mc mirror` výš.

## `x-aisha-povinne-za-behu: [FEDERATION_VAULT_KEY]`

Povinné za běhu, ne při parsování: broker bez klíče trezoru relací nenastartuje
(`loadConfig`, ADR-004). `${…:?}` v `environment:` by klíč vtáhl do build-time
množiny a Coolify by ho zapekl do `docker history` (brána
build-time-mnozina-vsech-compose, rohatka). Tohle pole je prosté jméno, žádná
interpolace — build-time množina ho nevidí, předlet nasazení
(`scripts/lib/povinne-promenne.mjs`: CI před nasazením, doktor fáze P, sync)
ho hlídá jako povinné a NEPRÁZDNÉ. Instance bez klíče tak skončí na předletu
s návodem (env-doktor → sync), ne zeleným nasazením a mrtvým brokerem.

## `FEDERATION_VAULT_KEY: "${FEDERATION_VAULT_KEY}"`

Trezor relací federovaného zdroje (ADR-004): klíč žije JEN tady, nikdy v DB (brána A15).
Bez `:?` (viz `x-aisha-povinne-za-behu` výš). Tři pojistky: předlet nasazení,
read-back sync-envs (kontrakt env-doktora, druh `hex`) a start brokeru.
