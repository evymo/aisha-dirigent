# AISHA Dirigent — Supervisor Status

> Auto-generated from AISHA Expert Overlay ruleset.
> **Do not edit manually** — regenerate via `npm run gen:ide -- --format=claude-overlay`.

Show the current state of the AISHA Dirigent runtime supervision overlay:
which hooks are registered, which rules they advise on, cooldown state,
backend connectivity, and active story context.

## Arguments: $ARGUMENTS

## Instructions

1. **Active story** — read `.aisha/story.json` and display story_id +
   updated_at. If absent, note "no active story; supervisor runs in
   global-rules mode".

2. **Hook inventory** — parse `.claude/settings.json` and report:
   - Per event (`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`):
     count of `_aisha`-marked hook entries vs total entries.
   - List the AISHA-managed hook commands (basename only, e.g.
     `aisha-advise-rpc.sh`).

3. **Cooldown state** — `ls /tmp/aisha-advise-*-${CLAUDE_SESSION_ID:-default} 2>/dev/null`
   and report which rules are currently in cooldown (rule_key extracted from
   filename, plus seconds since last fire). If `$ARGUMENTS` contains `clear`,
   `rm` the cooldown files for the current session.

4. **Backend connectivity check** (Vrstva 2 HTTP, deferred until backend deployed):
   - Inspect `.claude/settings.json` for `hooks.*` entries with `"type": "http"`
     pointing at the dirigent-supervisor endpoint. Report whether any are wired.
   - If none: report "Vrstva 2 not yet wired — running in local-only advisory mode
     (Vrstva 1)". This is the current default — see
     [docs/aisha-dirigent-supervisor-backend-deploy.md](docs/aisha-dirigent-supervisor-backend-deploy.md)
     for the deploy roadmap.
   - If wired but `${AISHA_MCP_TOKEN}` is empty: report "Vrstva 2 wired but token
     missing; HTTP hooks will return 401 / be ignored by the backend".

5. **Aisha-advisor subagent** — confirm `.claude/agents/aisha-advisor.md`
   exists and report its `tools` frontmatter (verifies read-only constraint).

6. **MCP server** — confirm `.mcp.json` lists `aisha-knowledge` server.
   Probe (best-effort) if reachable.

7. **Summary line** — single-line status emoji-free:
   `Story: <id|none> | Vrstva 1: N hooks | Vrstva 2: <state> | Vrstva 3: ready | Cooldown: K active`

## Notes

- This command is read-only — it inspects state, doesn't modify anything
  except optionally clearing cooldown files when `clear` is passed.
- Use this to debug why an advisory you expected didn't fire (most often:
  cooldown is active, file doesn't match the regex, or wrong file extension).
