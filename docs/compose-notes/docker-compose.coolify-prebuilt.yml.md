# docker-compose.coolify-prebuilt.yml — notes

Prose extracted from `docker-compose.coolify-prebuilt.yml` by `scripts/compose-extract-notes.mjs`.
The compose file is passed to Coolify as a command-line argument and competes
with ARG_MAX, so it carries configuration only.

Each heading is the configuration line the note was attached to.

## `services:`

docker-compose.coolify-prebuilt.yml

Edge stack (Frontend). Three containers:
  - web         : SPA frontend (nginx). Single domain ${APP_DOMAIN} via
                  Coolify auto-gen routing (works fine for single-domain).
  - mesh-router : NetBird agent + forwarding hop. NO public listener exposed
                  to Coolify Traefik. Klienti edge stacku k němu mají ROUTU
                  do rozsahu peerů a chodí přes něj JMÉNEM (viz níže).
  - edge-proxy  : Plain caddy:2.8 reverse-proxy on coolify network. Listens
                  on :80 and reverse_proxies na mesh JMÉNA cílů. The Traefik
                  labels live here (it has the listener).

Why split (the post-mortem of the failed combined attempt):
  We tried NetBird+Caddy in one container. Empirical A/B test proved that
  when NetBird agent is in the same netns as a Caddy listener, the
  listener becomes invisible to Coolify's Traefik provider when traffic
  arrives from the coolify network — NetBird's INPUT-chain firewall blocks
  inbound from non-mesh interfaces. Naked Caddy on the same network with
  the same labels works fine (200), Caddy+NetBird returns 502.

  Split fixes this:
    - mesh-router: agent only, NO local listener — the agent's INPUT
      firewall has nothing to filter (we forward via PREROUTING+DNAT,
      which traverses FORWARD chain, not INPUT).
    - edge-proxy : plain Caddy, naked on coolify network, OWN IP.
      Coolify Traefik discovers the listener and routes by Host header.
    - ⛔ DNAT PORTŮ 8080/3001 JE PRYČ (2026-08-21). Přepisoval cíl podle
      PORTU, takže uměl mířit na jedinou adresu (`CORE_MESH_IP`). Jakmile
      do mesh vstoupil druhý stack, port 8080 (imgproxy jádra i n8n) poslal
      veřejný provoz `mcp`/`dirigent` do jádra a přísný ingress ho odmítl
      `421 Host nepatri na tento port`. Port není adresa.
    - Dnes: klient (edge-proxy, extranet-auth) má `ip route` do rozsahu
      peerů přes mesh-router a míří JMÉNEM cíle + portem jeho veřejné tváře.
      mesh-router jen forwarduje: FORWARD ACCEPT, MASQUERADE na wt0 (reverzní
      cesta přes conntrack) a MSS clamp. Routu staví JEDINÝ sdílený skript
      `infra/mesh/mesh-client-route.sh`; bránou je pinovaná adresa
      mesh-routeru na síti `mesh-dns` (`NETBIRD_DNS_IP`), rozsah přichází
      jako `NETBIRD_PEER_CIDR` (jediný domov: `scripts/lib/derive-subnets.mjs`).
    - MSS clamping on FORWARD chain handles MTU mismatch (1500 → 1280).

Routing topology (after this refactor):
  client → pfSense (ACME *.${PUBLIC_TLD} wildcard, TLS termination)
        → HAproxy (hostname routing to frontend)
        → Frontend Coolify Traefik (just routes to backend container)
        → edge-proxy container (naked Caddy on coolify net, OWN IP)
        → reverse_proxy http://<prefix>-<služba>.mesh.<MESH_TLD>:<port>
        → routa do ${NETBIRD_PEER_CIDR} přes mesh-router (forward+MASQUERADE)
        → over wt0 / WireGuard → mesh-ingress cílového stacku (routuje HOSTEM)
        → kontejner služby

Sentinel `docker_compose_domains` entries (managed by
scripts/coolify-domain-doctor.mjs) keep Coolify's Traefik provider reading
the static labels on edge-proxy. mesh-router has no listener and no public
routes — sentinel for it just suppresses Coolify auto-gen.

Required env (Coolify UI):
  NETBIRD_STACK_KEY_FRONTEND  (reusable, type=reusable, ttl=10y)
  NETBIRD_DOMAIN           (default ${NETBIRD_DOMAIN})
  CORE_MESH_IP             (NetBird mesh IP of the core peer; required)
  MCP/DIRIGENT_DOMAIN      (generated by topology resolver)
  API_DOMAIN_PUBLIC        (generated by topology resolver)
  AUTH_DOMAIN_PUBLIC       (generated by topology resolver)

⛔ NAMĚŘENO 2026-09-26 na <fork> bez matrixu: `:?` tu bylo přísnější než
spotřebitel. Samostatný doktor prošel (hodnotu nesl starý `.env.coolify`), ale
uvnitř cold-startu fáze D padla: cold-start načítá šablonu `config/domains.env`

## `pki-init:`

─── mesh-router: NetBird agent + iptables DNAT (NO public listener) ─────
This container holds the WireGuard interface (wt0) and the routing
rules that translate edge-proxy's plain TCP traffic on coolify network
───────────────────────────────────────────────────────────────────────────
pki-init — assemble the mesh trust bundle before the agent enrols.

Identical to the core / integration / ledger stacks: the shared
infra/pki/assemble-ca-bundle.sh (baked into Dockerfile.pki-init) starts from
the SYSTEM root store, then appends the AISHA realm CAs — LIVE from the
pki-bridge, falling back to the baked copy only while the bridge is not up
yet (first cold-start wave). Edge was the one mesh peer without it.

WHY EDGE NEEDED IT (mesh outage 2026-07-17 -> 19). mesh-router pointed
SSL_CERT_FILE at /certs/pki/aisha-ca-bundle.pem, a file nothing here ever
wrote, and in Go that yields an EMPTY trust pool rather than a fallback to
the system store — so every TLS handshake failed:
    x509: certificate signed by unknown authority
The volume was declared `external: true, name: aisha_v2_pki-certs` on the
theory that the CORE stack fills one shared per-host volume. It cannot:
Coolify ignores `name:`/`external:` and scopes volumes per app — measured,
`aisha_v2_pki-certs` exists on NEITHER talos NOR giah while 30 empty
`*_pki-certs` volumes do — and core runs on giah while edge runs on talos,
so a per-host volume could not cross hosts anyway.

## `PKI_BRIDGE_URL: ${PKI_BRIDGE_URL:-}`

Referenced so coolify-sync-envs pushes it -> assemble-ca-bundle.sh fetches
the LIVE realm CA (baked-bundle fallback if the bridge isn't up yet).

## `mesh-router:`

into mesh traffic via wt0. It deliberately exposes NO ports to Coolify
Traefik — only edge-proxy reaches it (via Docker DNS on coolify network).

## `init: true`

PID-1 zombie reaper. In idle mode (NB_SETUP_KEY empty) PID 1 is a bare
`sleep infinity` that never wait()s, so the periodic healthcheck/enrollment
`timeout` helpers re-parent to it as defunct zombies and pile up. Incident
2026-06-13: ~28.8k `timeout` zombies on talos exhausted the host process
table → host-wide fork() EAGAIN → this container's own healthcheck could no
longer fork a shell → reported unhealthy → aisha-edge flapped. `init: true`
runs tini as PID 1, which reaps children so zombies can never accumulate.

## `- edge-proxy-data:/etc/netbird`

NetBird agent state. NetBird 0.70+ uses /var/lib/netbird/default.json
for persistent config (private key + peer ID + cached management info).
/etc/netbird is the LEGACY path (pre-0.70). Mount BOTH for forward
and backward compat, sharing the same named volume.

Critical: without persistent /var/lib/netbird, every container
restart re-enrolls with a fresh WireGuard private key → new peer ID
in mgmt → orphan records of previous enrollments → Signal rejects
incoming streams ("didn't receive a registration header").

## `- pki-certs:/certs/pki:ro`

AISHA PKI CA bundle — kept for future mesh re-enablement once
netbird-internal-tls is fixed. Currently unused since we use the
public LE-cert path (system CAs) for fresh enrollment.

## `- mesh-diag:/diag`

TEMPORARY — diagnostic scaffolding (Step 1: investigate mesh state).
web nginx mounts this volume RO at /usr/share/nginx/html/__mesh_diag
for inspection via ${APP_DOMAIN}/__mesh_diag/status.txt. Remove
once mesh routing is confirmed working.

## `extra_hosts:`

Internal mesh resolution — REQUIRED under the .internal mesh TLD (which has
NO public DNS record, by design: a missing mapping fails loud with NXDOMAIN
instead of silently resolving to the public edge IP and NAT-hairpin timing
out — the root cause of the edge mesh-router enroll failure).

Mirror the backend/integration/cosmos netbird-agents: resolve the mesh
control-plane host to the Frontend LAN IP (NETBIRD_MGMT_HOST, e.g.
<frontend-lan-ip>) where the netbird-internal-tls caddy publishes :33073.
host-gateway is the same-host fallback (this container runs ON the Frontend
host, so the docker host-gateway also reaches the published :33073). This
replaces the previous public ${NETBIRD_DOMAIN}:443 NAT-hairpin path that
"may fail on cold-start" — now a proven, deterministic internal path.

Od 2026-08-21 to NENÍ cíl DNATu (ten je pryč) — je to MĚŘIDLO, jestli peer

## `NB_SSL_TRUST_BUNDLE: /certs/pki/aisha-ca-bundle.pem`

Trust the AISHA PKI chain for the .internal mgmt/signal endpoint —
same pattern as the core/integration/cosmos agents (SSL_CERT_FILE is
honored by netbird's Go TLS stack; NB_SSL_TRUST_BUNDLE is the
netbird-native knob). The bundle is baked into the shared per-host
`aisha_v2_pki-certs` volume by the core stack's pki-init and mounted
RO at /certs/pki above. Without these the agent rejects the
netbird-internal-tls cert ("x509: certificate signed by unknown
authority") — fresh edge enrollment was impossible (2026-07-09).

## `entrypoint:`

─── ENTRYPOINT — every $ is escaped to $$ so that Docker Compose
passes the literal `$` to the container. The container shell then
expands `${VAR}` from CONTAINER environment (which is populated by
the `environment:` block above). Without `$$`, compose substitutes
with its OWN env (which doesn't have these vars) → empty strings →
iptables and netbird get blank arguments → silent failure.

connectivity is verified via edge-proxy's actual reverse_proxy
response. We don't gate edge-proxy on this — depends_on uses
service_started (not service_healthy) so a slow NetBird enrollment
doesn't block the deploy.

## `edge-proxy:`

─── edge-proxy: naked Caddy reverse-proxy ───────────────────────────────
Plain caddy:2.8.4-alpine on coolify network with own IP. Coolify
Traefik provider discovers the :80 listener and routes by Host header

## `- "traefik.http.services.mesh-svc.loadbalancer.server.port=80"`

── STATIC TRAEFIK MESH ROUTES ────────────────────────────────────
Cert chain (NOT Traefik's job — Traefik just routes):
  client → pfSense (ACME, *.${PUBLIC_TLD} wildcard cert termination)
        → HAproxy (hostname routing) → Frontend Traefik (this layer)
        → THIS container (edge-proxy) on :80 → Caddy demux → mesh

Why static labels (not docker_compose_domains for these 3 hosts):
  Coolify auto-gen for multi-domain entries can't determine the
  right upstream port for non-HTTP images, and override labels
  are shadowed (last-write-wins). Static labels work cleanly here
  because this container has its OWN listener on :80 (Coolify
  Traefik provider correctly discovers it).

Why LITERAL hostnames (not `${VAR}`):
  Coolify ALWAYS escapes `$` → `$$` in label values. ${MCP_DOMAIN}
  becomes literal `$${MCP_DOMAIN}` → no Host() match → 404.
  Hostnames here MUST match config/domains.env (single source of truth).
  See `~/.claude/.../memory/feedback_coolify_label_dollar_escape.md`.

`tls.certresolver=letsencrypt` is a LOOKUP HINT for Traefik's cert
storage namespace (where the wildcard *.${PUBLIC_TLD} already lives) —
NOT an acquisition trigger. Without it `tls=true` alone leaves
Traefik without a cert to use → router NOT registered → 404.

## `edge-proxy-data:`

NetBird agent state (WireGuard private key, peer ID, cached mgmt info).
Named `aisha_v2_edge-proxy-data` because the original combined
aisha-edge-proxy container (pre-split) created this volume during its
successful enrollment as peer `edge`. By REUSING that name here:
 - If the volume still exists on Frontend host, mesh-router re-attaches

## edge-proxy `extra_hosts` — LAN bypass for a mesh-disabled multi-server deploy

With `MESH_ENABLED=false` the edge-proxy falls back from `mesh-router` to the
`*_UPSTREAM_PUBLIC` targets. Those are INTERNAL-zone vhosts
(`<svc>.backend.${INTERNAL_TLD}`) served by the **backend** server's Traefik, but
public DNS resolves them to the ingress host rather than to that server — so every
api/auth call through the edge 502s while the backend is perfectly healthy.

Observed 2026-07-21 on a two-server deploy (edge=frontend/Varra,
core=backend/Giah): `web.<public>` served 200 while `api.<public>` stayed 502, and
the backend's PostgREST was returning real rows the whole time.

`extra_hosts` pins those vhosts to the backend's LAN IP. The Host header is
preserved, so the backend Traefik still matches its own vhost — this replaces only
the name resolution, exactly like the netbird control-plane bypass in the same file
(which dodges the ingress and its LE-cert SNI on a LAN interface for the same
reason).

Env-gated and inert by default: `BACKEND_LAN_IP` unset resolves to `host-gateway`,
a no-op on single-server deploys and whenever the mesh is enabled.

**Both interpolated keys must be in the build-time allowlist**
(`scripts/lib/coolify-buildtime-envs.sh`): Coolify parses the whole compose with
`build-time.env` only, so a runtime-only key interpolates to `""`, the entry
degenerates to `":host-gateway"`, and the compose parse hard-fails with
`extra_hosts must be a mapping` — the 2026-07-09 incident that silently kept edge
on a 3-day-old container. `API_DOMAIN` was already covered by the
`(MCP|API|AUTH|DIRIGENT)_DOMAIN` branch; `KEYCLOAK_DOMAIN` and `BACKEND_LAN_IP`
were added for this.

## `api_tls` / `auth_tls` — upstream TLS trust on the internal hop

The SNI note above assumes the backend Traefik serves a wildcard cert for
`*.backend.${INTERNAL_TLD}`. On a fork whose internal TLD has no such cert
provisioned, that name is not publicly resolvable, so ACME can never issue for it;
Traefik answers with its self-signed DEFAULT cert, and Caddy — which verifies
upstreams by default — refuses the connection and returns 502 for every api/auth
call. `core-mesh-ingress` already does `tls_insecure_skip_verify` for this
identical backend hop.

The block is emitted **only when the resolved upstream is `https://`**, on purpose:
`tls_insecure_skip_verify` *implies* TLS in Caddy, so emitting it for the plaintext
mesh upstream (`http://mesh-router:PORT`) would force TLS onto a cleartext listener
and break the mesh path.

Provisioning the backend wildcard cert makes this block inert by itself — that is
the proper fix; this keeps a mesh-disabled fork serving in the meantime.

## `EDGE_DOOR_MODE: ${EDGE_DOOR_MODE:-off}`

Dveře na edge: `off` (výchozí) | `observe` | `enforce`. Zapíná se VĚDOMĚ jednou
proměnnou, ne vedlejším účinkem nasazení — deploy sám nic nezavře.

| stav | dveře | evidence |
|---|---|---|
| nenastaveno / `off` | otevřeno | nic se nezapisuje |
| `observe` | **otevřeno** | zapisují se adresy přístupů |
| `enforce` | zavřeno, verdikt dává `svc-knock` | — |

Hodnota se normalizuje na JEDNOM místě (malá písmena, bez mezer) a **neznámá
hodnota edge NESPUSTÍ**. Do 2026-09-19 se četla syrová, takže `Observe` i
`enforce ` tiše spadly na `off` — tedy na otevřeno, u proměnné, jejímž jediným
smyslem je zavírat. Překlep nemá být rozdíl mezi zavřeno a otevřeno.

**Doktrína je tu jednotná: u bezpečnostního přepínače je neznámá hodnota překlep
operátora, ne důvod k otevření.** Platí totéž co u extranetu výš („radši
nedostupné než otevřené") a u gatewaye (`services/gateway/src/config.ts` odmítne
start, když jsou dveře zapnuté a chybí `GATEWAY_TRUSTED_PROXIES`). Varování v logu
nikoho nezastaví — kdo napsal `enfroce`, spoléhal na zavřeno.

`observe` slouží k tomu, aby šlo ZMĚŘIT, kdo na plochu chodí, dřív než se zavře —
jinak seznam povolených adres vzniká až z reklamací po výpadku přístupu. Zapne
filtrovaný přístupový log Caddyho do vlastního úložiště (`<prefix>_edge-pristupy`,
odděleně od kryptografického stavu netbirdu). Doba uchování je deklarace
`EDGE_ACCESS_RETENTION_DAYS` (výchozí 30 dní) — a rotace Caddy 2.8 ji SAMA
NEDRŽÍ; drží ji úklid, viz následující sekce.

Minimalizace se děje PŘI ZÁPISU (filtr Caddy), ne až při čtení. Evidence nese
jen `request.client_ip`, `request.remote_ip` (kontrola, že měříme klienta, ne
proxy), `request.host`, `request.method`, `status`, `ts` a technické značky
`level`/`logger`/`msg`. Hlavičky (Cookie, Authorization, User-Agent), URI
s query stringem, TLS, zdrojový port, protokol, velikosti a doba vyřízení se
nezapíšou vůbec. Sadu měří `npm run e2e:edge-uklid` na skutečném řádku.

Záměrně NEvede přes `forward_auth` na `svc-knock`: to by knock dostalo do kritické
cesty každého požadavku a jeho výpadek by nebyl „dveře nehlídají", ale 502 na celou
veřejnou plochu. Sledování nesmí být rizikovější než stav, který nahrazuje.

⚠️ **`observe` je zpracování osobních údajů.** IP adresa je osobní údaj, takže před
zapnutím potřebuje instance záznam o činnostech zpracování podle čl. 30 GDPR —
účel, právní základ, minimalizace, doba uchování a hlavně KONEC. Účel končí
rozhodnutím dverníka; nechat `observe` běžet dál je zpracování bez účelu. Samotný
záznam patří do instance-data, ne sem.

Podklad pro rozhodnutí dělá `scripts/dvernik-evidence.mjs`. Bez doručeného
`GATEWAY_TRUSTED_PROXIES` z té evidence ODMÍTNE navrhovat — jinak by do
`SPA_STATIC_ALLOW` propašoval adresu proxy a dveře by byly vyhlášené, ale neúčinné.
Touž zásadu drží `services/gateway/src/config.ts`.

## `EDGE_ACCESS_RETENTION_DAYS: ${EDGE_ACCESS_RETENTION_DAYS:-30}`

Úklid evidence adres. Lhůta N ve dnech je **deklarace** s jediným domovem:
kontrakt env-doktora, `static 30`. Doktor (cold-start i redeploy) doplní jen
CHYBĚJÍCÍ klíč, operátorem zkrácenou lhůtu nepřepíše (změřeno: chybí → 30,
14 → 14). Compose ji vyžaduje (`:?`) a nikde ji nedosazuje — výslovně prázdná
lhůta nasazení zastaví nahlas. Generátor tajemství ji záměrně nevydává: dva
zapisovatelé by měli dvě sémantiky prázdna.

**Mez: záznam žije nejvýš N + 1 dní** (plus 15 s intervalu úklidu). Ne N: aktivní
soubor se řeže jednou za 24 h a archiv se maže, až je i jeho NEJNOVĚJŠÍ záznam
(mtime archivu) starší než N dní. Tuhle mez uvádí i záznam o činnostech zpracování.

### Proč úklid a ne `roll_keep_days`

⛔ NAMĚŘENO 2026-09-25: edge je `caddy:2.8.4` a jeho zapisovač (lumberjack) rotuje
**jen podle velikosti**. `roll_keep_days` maže odrolované soubory; aktivní
`pristupy.log` pod 10 MiB drží záznamy libovolně dlouho. Při malém provozu byla
deklarace 30 dní a skutečnost měsíce. Navíc `roll_keep_days 0` znamená „navždy".

Časová rotace (`roll_interval`, `roll_at`) je až v **Caddy ≥ 2.11.1** (přechod na
timberjack, caddyserver/caddy#7244). ⏭ **Až bude edge na ≥ 2.11.1, úklid se nahradí
nativní rotací** (`roll_at` jednou denně + `roll_keep_for`). Upgrade pinu jde
samostatně — `2.8.4` je připnutý na čtyřech službách a nepatří do změny dveří.
`roll_keep_days` do té doby zůstává jako druhá pojistka pro zálohy lumberjacku.

### Proč ho vykonává healthcheck — NEPŘESOUVAT do smyčky

Smyčka na pozadí umře potichu a lhůta přestane platit, aniž by to kdo viděl.
Healthcheck Docker spouští každých 15 s, dokud kontejner běží — vykonavatel tu
nemůže zemřít, takže „hlídka bez hlídky" mizí strukturálně, ne detekcí.

Obráceně platí stejně tvrdě: **výsledek úklidu NESMÍ ovlivnit verdikt zdraví.**
Edge nemá autoheal; unhealthy = Traefik ho vyřadí = 503 na celou veřejnou plochu
a nic ho nerestartuje. Proto nejdřív `wget` (verdikt), pak úklid pod `timeout 2`,
a konec podle `wget` normalizovaný na 0/1 (kód 2 si Docker rezervuje). Úklid běží
i při nemocném edge — lhůta neplatí jen za zdraví. `find` každých 15 s je levný
(adresář s desítkami souborů), škrtit ho netřeba.

### Pořadí řezu — přežije zabití timeoutem

1. `tr -d '\000' < pristupy.log > .rez-rozpracovano` (kopie bez děr, viz níž)
2. `mv .rez-rozpracovano pristupy.log.<datum UTC>`
3. zkrácení aktivního souboru (`: >`), ne smazání — Caddy drží deskriptor
4. `touch .rez`

Zabití před `mv` nechá jen dočasný soubor (smaže se po 10 min), nikdy polovičatý
archiv pod jménem, které nástroj dvorníka čte jako hotovou evidenci. Zabití mezi
`mv` a zkrácením: další průchod řez zopakuje a TÝŽ den přepíše týž archiv jeho
nadmnožinou. Přes půlnoc UTC vzniknou dva archivy s překryvem — duplicitní
řádky, žádné ztracené. Zkracuje se i po selhání `cp` (plný disk): lhůta má
přednost před evidencí. První průchod bez `.rez` řízne hned, aby obsah z doby
před úklidem nečekal na velikost.

**Poctivě: řádky zapsané mezi kopií a zkrácením (milisekundy) se ztratí.**

⛔ NAMĚŘENO E2E 2026-09-25 (předpoklad byl opačný): lumberjack nově založený
soubor — první start i každou rotaci — otevírá **bez `O_APPEND`**. Po zkrácení
proto Caddy píše dál na svůj starý posun a před novými řádky vznikne **řídká díra
z nul**. Data v ní nejsou (zkrácení je uvolnilo, na disku díra nezabírá místo),
ale `cp` by nuly zkopíroval do archivu a první řádek za nimi by nešel přečíst.
Proto se archiv dělá přes `tr -d '\000'` (Caddy v JSON nulu nikdy nezapíše
surovou, jen escapovanou) a `dvernik-evidence` nuly před čtením zahodí.
Zdánlivá velikost aktivního souboru tím roste do `roll_size`; lumberjack si
velikost počítá sám a rotuje podle ní, takže rotace přijde dřív, než soubor
naplní 10 MiB skutečných dat. Neškodí — záloha se maže týmž pravidlem.

## `netbird_block=""` (edge-proxy)

Veřejná tvář NetBirdu (`netbird.<public-tld>`) — dashboard, REST `/api`, gRPC
managementu a signalu, relay WebSocket — je jediná veřejná plocha, která **nejde
přes edge do meshe**. Je to zdokumentovaná výjimka (majitel 2026-09-16): NetBird
mesh staví, takže v ní být nemůže. Edge proto obsluhuje veřejné jméno a posílá
ho na **přímou tvář** `NETBIRD_DOMAIN_DIRECT` (zóna `*.backend`, kterou pfSense
směruje na uzel služby). Není to vzor pro jiné služby.

**Naměřeno 2026-09-16** (guru):

- Veřejné jméno bylo zaregistrované u `netbird-proxy` na uzlu služby. Provoz tam
  nedorazí — pfSense posílá veřejnou zónu na uzel s edge → `/`, `/api/users`,
  `/relay` i gRPC `GetServerKey` vracely **404**. Tamní Traefik navíc pro to
  jméno servíroval `TRAEFIK DEFAULT CERT`: ACME výzva přistála na edge, ne u něj.
- Přímá tvář téhož proxy odpovídala správně z edge kontejneru i zvenku, s platným
  certifikátem: `/` 200, `/api/users` 401, `/relay` 426, gRPC `GetServerKey`
  `grpc-status: 0`.
- Agenti meshe veřejnou tvář **nepotřebují**: zapisují se i relayují přes
  `netbird.<mesh>:33073` (log agenta: `connected to Relay server:
  rels://…:33073/relay`, `successfully dialed via: WS`). Jméno
  `rels://netbird.<public>:443/relay` v jejich logu je identita relay serveru
  (`NB_EXPOSED_ADDRESS`), ne adresa, kam vytáčejí. Veřejná tvář je pro lidi —
  dashboard, desktopový a mobilní klient.

**Proč bez `tls_insecure_skip_verify`**: na rozdíl od upstreamů ve vnitřní zóně
nese přímá tvář veřejně ověřitelný certifikát, takže se ověřuje; SNI je jméno
upstreamu.

**Proč `flush_interval -1`**: management (`Sync`) i signal (`ConnectStream`)
drží dlouhé gRPC streamy a relay je WebSocket. Skok Traefik → edge-proxy je
HTTP/1.1, takže Caddy by odpověď bez `Content-Length` za stream neuznal
a bufferoval by ji.

Doména se registruje u `edge-proxy` (domain-doctor i deploy-init) jen tehdy, když
existuje přímá tvář — jinak by edge měl router bez trasy. U `netbird-proxy`
zůstává jen přímá tvář.

## `external_faces_block=""` (edge-proxy)

Veřejné tváře aplikací, které instance **nenasazuje** (vlastní Coolify app, cizí
repozitář) — JEDNA proměnná instance, ruční deklarace operátora (env-doktor ji
drží jako `static`, derivace ji čte jako vstup resolveru):

```
EXTERNAL_FACES="<subdomain>=<container>:<port>@<via>, …"
EXTERNAL_FACES="partner-api=partner-api:8000@source-broker"
```

Další aplikace = úprava hodnoty, ne commit.

Cesta: `edge-proxy` → `http://<prefix><subdomain>.<mesh>:<port>` (mesh DNS míří na
peer stacku `via`) → mesh-ingress stacku `via` → `<container>:<port>`.
Derivace vydá tři věci a žádnou z nich se nepíše ručně:

- trasu `port|<mesh>,<veřejné>|<container>:<port>` do `<PEER>_MESH_INGRESS_ROUTES`
  stacku `via`,
- `EDGE_EXTERNAL_FACES` (`<veřejné>|<mesh upstream>;…`) pro tuhle smyčku,
- `EDGE_EXTERNAL_FACE_HOSTS` pro Traefik kontrakt edge-proxy (domain-doctor
  i deploy-init).

**Proč ne port na LAN a router vedle** (první návrh, 2026-09-18): je to přesně
boční cesta, kterou pravidlo „veřejné jde přes edge do meshe" zakazuje, a
Traefik na uzlu služby by si pro veřejné jméno žádal certifikát, jehož výzva
dorazí na uzel s edge.

**Proč aplikace není mesh peer**: dostala by setup klíč a stala by se nájemníkem
meshe se vším, co to obnáší. Přes `via` zůstává mimo; stačí, aby byla vidět
z netns agenta stacku `via` — tedy na **jeho** docker síti pod jménem
`container` (název compose služby nebo `aliases:`, ne `container_name`, ten
Coolify přejmenuje). U `source-broker` je to instanční `${MESH_DNS_NETWORK}`.

**Proč se Host nepřepisuje** (na rozdíl od `companion_block`): mesh-ingress zná
i veřejné jméno (je v trase), takže ho pustí dál; aplikace mimo platformu mesh
jméno nezná a skládá z Hostu vlastní absolutní adresy. `X-Forwarded-Proto
https` nese informaci o TLS, které skončilo na pfSense.

**Bez meshe se tvář nevydá** — derivace to řekne (`WARN … se NEVYSTAVÍ`) a obě
proměnné jsou prázdné. Prázdné se vydávají i bez deklarace, aby odebraná tvář
z `.env.coolify` zmizela. Brána: `cizi-verejna-tvar-vede-meshem`.

## `EDGE_EXTERNAL_FACES: ${EDGE_EXTERNAL_FACES:-}` — cizí veřejné tváře (review 2026-09-19)

**Obsah položky** se ve smyčce edge hlídá (jen `[A-Za-z0-9.:/_-]`): jde do Caddyfile
doslova a mezera, `{`/`}` nebo druhé `|` by rozbily syntaxi CELÉHO souboru —
nenaběhla by žádná veřejná tvář, ne jen ta vadná. Vadná položka se přeskočí nahlas
a nespotřebuje číslo matcheru. Derivace takovou hodnotu nevydá; je to pojistka proti
ruční úpravě trezoru. Ověřeno v alpine (busybox sh) 2026-09-24 a hlídá to brána
`cizi-verejna-tvar-vede-meshem` — spouští úsek pod `set -u`, protože entrypoint po
mesh routě dělá `set +e`, který vypne jen errexit a nounset nechá platit.

**Pořadí nasazení:** mesh DNS (`netbird-dns-provision.mjs --apply`) až PO nasazení
stacku `via` — záznam míří na IP jeho peeru; bez živého peeru jméno odpadne do
„NEVYŘEŠENO" a tvář je na edge i v trase, ale bez DNS → 502 (přeloží se a nespojí).
Cílová aplikace musí být na síti agenta `via` dřív, než se tvář ověřuje — jinak
ingress krátké jméno nenajde a přes search doménu ho přeloží na veřejnou IP →
`dial … i/o timeout` → 502 (naměřeno 2026-09-19).

**Návrat zpět:**

1. odebrat položku z `EXTERNAL_FACES` (nebo celou proměnnou vyprázdnit);
2. env-doktor → `EDGE_EXTERNAL_FACES(_HOSTS)` a `<PEER>_MESH_INGRESS_ROUTES` stacku
   `via` se přepočtou (prázdné se vydávají vždy);
3. sync env + redeploy stacku `via` (tabulka mesh-ingress) a edge;
4. domény edge-proxy (`coolify-domain-doctor.mjs --only=edge --apply` nebo
   deploy-init) — hostitel z Traefik kontraktu zmizí.

Co zůstane: **DNS zóna** mesh jména. `netbird-dns-provision` maže jen zóny se svou
značkou, a dokud ji hledá v `description`, neprořízne nic: NetBird 0.70 zónu vrací
BEZ `description` (naměřeno 2026-09-19). Značku do `name` přesouvá samostatný
upstream PR #1022 (`fix/dns-zony-znacka`); do jeho sloučení se zbylá zóna odstraní
jen ručně v NetBirdu. Je neškodná — míří na peer `via` a trasa už neexistuje.

**Negativní sonda po návratu:** `curl -s -o /dev/null -w '%{http_code}' https://<veřejné>/`
→ `404`. Dokud Traefik doménu ještě routuje na edge, odpoví edge catch-all
`edge-proxy: unknown host (no rule matched)`; po kroku 4 odpoví 404 už Traefik.
Cokoli jiného (502, 200) znamená, že některá rovina tvář pořád nese.
