# PKI Bridge — Autonomous Certificate Issuance

> **Status:** Alpha (2026-05-06, commit `aa9acd16`)
> **Service:** `svc-pki-bridge` (Fastify, port 3040)
> **Compose:** `docker-compose.coolify-pki.yml`

---

## Overview

`svc-pki-bridge` is the machine-to-machine consumer of JWT tokens for autonomous
TLS certificate issuance. It connects Keycloak ROPC authentication to OpenXPKI's
RPC enrollment engine with HMAC-signed auto-approval.

**Flow:**
```
ROPC client (aisha-pki-bootstrap)
    │
    ▼
Keycloak → access_token (aud=pki-proxy)
    │
    ▼
POST pki-bridge:3040/v1/issue
  { hostname, sans[], comment }
    │
    ├─ JWT validation (aud=pki-proxy, JWKS from Keycloak)
    ├─ SAN policy check (*.mesh.aisha.internal, *.backend.id3a.cz)
    ├─ Generate EC P-384 key + PKCS#10 CSR (openssl CLI)
    ├─ HMAC-sign CSR → OpenXPKI RPC RequestCertificate
    │   (auto-approved: HMAC = 1 approval point)
    └─ Return { certificate, privateKey, chain, certIdentifier }
```

## Architecture

### Components (in docker-compose.coolify-pki.yml)

| Service | Role |
|---------|------|
| `pki-init` | Renders OpenXPKI config templates using generated Coolify env secrets |
| `pki-server` | OpenXPKI CA engine (signing, enrollment) |
| `pki-client` | OpenXPKI protocol wrappers (RPC, EST, SCEP) |
| `pki-webui` | Apache reverse proxy to OpenXPKI client socket |
| `pki-auth` | OAuth2 Proxy for WebUI (human access) |
| `pki-bridge` | **This service** — machine JWT consumer for cert issuance |
| `pki-renewer` | Cron sidecar — auto-renews certs every 6h via bridge |

### HMAC Flow (Cold-Start SoT)

```
aisha-cold-start.sh:
    ├─ preserve_or_gen OPENXPKI_RPC_HMAC openssl rand -hex 32
    └─ write OPENXPKI_RPC_HMAC to .env.coolify

coolify-deploy-init.sh:
    └─ push OPENXPKI_RPC_HMAC to aisha-pki Coolify env

pki-init:
    ├─ fail fast if OPENXPKI_RPC_HMAC is missing
    └─ sed __PKI_RPC_HMAC__ in rendered OpenXPKI config

pki-bridge:
    └─ reads OPENXPKI_RPC_HMAC from env

pki-server:
    └─ reads rendered config.d/realm/*/rpc/generic.yaml
            → same HMAC → auto-approved enrollment
```

The HMAC is generated platform data, not a runtime sidecar artifact. There is
no `pki-shared`/`rpc-hmac.key` fallback, so OpenXPKI and pki-bridge cannot drift
by reading different runtime files.

### SAN Policy

Configured via `PKI_ALLOWED_SAN_PATTERNS` env (comma-separated glob patterns):
- `*.mesh.aisha.internal` — mesh TLS certs
- `*.backend.id3a.cz` — internal service certs

Bridge rejects any SAN not matching at least one pattern (HTTP 403).

## Deployment

### First-time Setup

1. Keycloak: `aisha-pki-bootstrap` client must exist with:
   - `directAccessGrantsEnabled: true` (ROPC)
   - Audience mapper → `pki-proxy`

2. Coolify env vars for aisha-pki:
   - `AISHA_PKI_BOOTSTRAP_CLIENT_SECRET` — from Keycloak
    - `AISHA_PKI_BOOTSTRAP_PASSWORD` — user password
    - `OPENXPKI_RPC_HMAC` — generated by `scripts/aisha-cold-start.sh`

3. Deploy: `node scripts/aisha-redeploy.mjs --only=pki --yes`

### Scripts

| Script | Purpose |
|--------|---------|
| `scripts/pki-bridge-deploy.mjs` | Set HMAC + renewer creds in Coolify, redeploy |
| `scripts/pki-issue-internal-cert.sh` | Manual cert issuance via ROPC + bridge |

## pki-renewer (Self-Healing Sidecar)

Alpine container running every 6h:
1. ROPC token acquisition from Keycloak
2. POST to pki-bridge `/v1/issue` with bearer JWT
3. Log cert issuance or error

The renewer captures HTTP status codes explicitly (no `curl -f`) so errors
from the bridge are visible in container logs.

## Troubleshooting

### "Bridge returned empty cert"

**Root cause (fixed aa9acd16):** Apache's port 80 VirtualHost was missing the
`/rpc` proxy rule. The bridge calls `http://pki-webui:80/rpc` (internal Docker
network, plain HTTP), but Apache only proxied `/rpc` on port 443 (HTTPS).
Fix: Added `RewriteRule` for `/rpc` on port 80.

### HMAC Mismatch

If certs fail with approval errors, verify HMAC consistency:
1. Check the `OPENXPKI_RPC_HMAC` value exists in the aisha-pki Coolify env.
2. Check rendered `config.d/realm/<realm>/rpc/generic.yaml` (hmac: value).
3. Both must match. If not, rerun `scripts/coolify-deploy-init.sh` and redeploy pki.

### OpenXPKI Realm Not Initialized

If the `orchestration-plane` realm has no active CA cert, OpenXPKI RPC will
fail. Check pki-server logs and OpenXPKI WebUI for realm status.
