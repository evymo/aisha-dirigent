# AISHA Platform — Final Draft for the official RC

> Historical document (status as of 2026-04-23). The current public preview is described in [docs/release/PUBLIC_PREVIEW.md](docs/release/PUBLIC_PREVIEW.md).
> This document summarizes what the project really is today, what it should present publicly, and what still needs to be finished before the official RC.

## What the project already is

AISHA Platform is a self-managing platform that connects product, development, workflow orchestration, knowledge systems, and operations into one system. It is no longer just a proof of concept; at the same time, it is still going through the final round of public documentation and release-message cleanup.

## What can already be communicated publicly

- The existence of the platform stack and its main architecture
- AISHA Dirigent as the orchestration layer for work and decisions
- The MCP knowledge layer and expert-rule usage
- The workflow backbone through n8n
- Keycloak-based identity and branded communication
- The direction toward a more autonomous agent platform

## What still needs to stay under control before the official RC

- Public documents must clearly separate the public set from internal runbooks
- English versions of the core documents must cover at least README, Credits, Architecture, Roadmap, and Final Draft
- Publicly tracked configuration files must not contain concrete bearer tokens or local access keys
- README and index files must not point to missing or misleading documents

## What the official RC is supposed to mean

The official RC is not “the finished world.” It is the first version that has:

- a consistent identity
- a defensible architecture
- understandable public documentation
- safely publishable content
- realistically described next steps

The project is far enough along to enter official RC preparation. The critical question is no longer “does it exist?” but “is the public face of the project as disciplined as its technical core?”
